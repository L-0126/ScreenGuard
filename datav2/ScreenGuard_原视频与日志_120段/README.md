# README

### 数据文件夹包含：

| 名称         | 用途                                                         |
| ------------ | ------------------------------------------------------------ |
| `index.html` | **看数据** 每行写着这段做了什么，点「播放录像」「完整日志」或「Agent 动作」即可查看。 |
| `index.csv`  | **写Python批量读数据** 每行一个会话，包含编号、数据划分、时长、文件路径和对应的标签。 |
| `v1_84/`     | 84 段主数据，涵盖编辑、复制粘贴、改名、附件操作等。其中旧批回归 48 段，训练 16 段，验证 10 段，测试 10 段。 |
| `blind_36/`  | 36 段独立盲测，用于检查**最初复制的原文有没有粘贴到目标窗口并保存**。粘贴原文、改贴另一段文字、只输入 `x` 各 12 段。 |

### **每个会话文件夹里都有相同的五个文件**：

| 文件              | 它能回答什么                                                 |
| ----------------- | ------------------------------------------------------------ |
| `video.mp4`       | **屏幕上实际发生了什么？** 原始连续录屏，可以看到窗口切换、文本出现、文件名变化等。 |
| `logs.json`       | **系统观察到了什么？** ScreenMonitor 的完整事件记录，例如前台窗口切换、剪贴板文字变化、文件打开或改名。 |
| `keyevents.json`  | **哪些系统事件值得先看？** ScreenMonitor 筛选、整理出的关键事件。这里的 `key` 指“关键”；查 `Ctrl+V` 这样的具体按键，要看下一份文件。 |
| `actions.jsonl`   | **Agent 发出了什么操作？** 每行一条调用，记录工具、参数、目标窗口和调用时间。用 VS Code 打开，搜索 `hotkey` 就能找快捷键操作。 |
| `clock_sync.json` | **这条操作对应视频第几秒？** 里面有录屏起始时间和起止同步标记，用来把动作、系统日志和视频对到同一时间轴。 |

### 除mp4外的四个文件如何读：

拿 `blind_36/CX-1246A655BD/` 这次粘贴实验举例。`{}` 包住一条记录，`[]` 包住一组记录，`.jsonl` 表示**每行各写一条独立的 JSON 记录**。

#### `logs.json` 和 `keyevents.json`：一个数组里放多条系统事件

这段的 `logs.json` 有 **14 条事件**。下面这条排在第 5，Python 里用 `logs[4]` 取出。它也是 `keyevents.json` 唯一保留的事件，所以后者的结构是这样：

```
[
  {
    "timestamp": "2026-11-23T04:51:58.829",
    "event_type": "clipboard_text",
    "app_name": "mousepad",
    "content_preview": "Orbit ticket 8D0A1C\nRoom 10 lists five sample entries.\n"
  }
]
```

读成人话就是：**北京时间 04:51:58.829，监测器观察到剪贴板里出现了这段文字。** `\n` 表示原文中的换行。这条记录能告诉你复制了什么。要判断文字后来有没有进入目标窗口，还要看动作和画面。

#### `actions.jsonl`：每行是一次调用

这个文件有 **15 行调用**。下面抽出其中三行，行与行之间没有逗号，外面也没有一对总的 `[]`。

```
{"action_id": 7, "tool": "hotkey", "arguments": {"keys": ["ctrl", "c"]}}
{"action_id": 10, "tool": "hotkey", "arguments": {"keys": ["ctrl", "v"]}}
{"action_id": 12, "tool": "hotkey", "arguments": {"keys": ["ctrl", "s"]}}
```

这里能直接读出 **第 7 次调用发出复制，第 10 次发出粘贴，第 12 次发出保存**。展开原文件里的第 10 次调用，`arguments.window_id` 是接收按键的窗口，`controller.sent_unix_ns` 是发出调用的时间，单位是纳秒。用 Python 读取时，普通 `.json` 用 `json.load(f)` 读整个文件，`.jsonl` 则逐行用 `json.loads(line)`。

#### `clock_sync.json`：整份文件是一份对时说明

```
{
  "input_start_unix_seconds": 1795380711.507051,
  "anchors": {
    "START": {"first_changed_pts_s": 2.75},
    "END": {"first_changed_pts_s": 32.375}
  }
}
```

`input_start_unix_seconds` 表示**视频第 0 秒对应的时刻**。`START` 和 `END` 是用来核对时钟的两个画面标记，这段视频里分别在第 2.750 秒和第 32.375 秒首次出现变化。

它最实用的地方，是能把 `actions.jsonl` 里的时间换成播放器进度：

**视频位置（秒）= `sent_unix_ns` ÷ 10 亿 − `input_start_unix_seconds`**

用第 10 次调用计算，`Ctrl+V` 在视频 **9.846 秒**发出。把播放器拖到 **10.000 秒**，就能看到文字已经出现在左侧目标窗口。这样你就把“系统看到了什么”“Agent 做了什么”“画面何时变化”三件事对上了。
